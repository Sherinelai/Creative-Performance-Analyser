# Learnings — session 8f929c5f-1f0e-4395-9e7c-b3abc8459d64

## 2026-08-17 — 8f929c5f
- **Finding:** `analytics.daily_attr_event_d7.is_video_creative` does not describe the serving
  format and cannot be used to classify Video vs Non-video. Over one baked day: ~3,900 creatives
  with $200K+ of spend sat on VAST `inventory_format`s while the flag said `'false'`; a few hundred
  non-VAST creatives said `'true'`; and a third value, `'UNMATCHED'`, exists and fell into Non-video
  under the old `String(c.is_video)==='true'` ternary. Per campaign it is decisive rather than noisy
  — 82323 has 40 of 80 creatives on VAST formats and the flag marks **0** as video; 38469 has 10 VAST
  creatives against a flag count of 1. The flag is unstable *within* a creative too: 38 of 91,634
  creatives carried two different values in one day, so with `is_video` sitting in the 17-column perf
  `GROUP BY` the surviving row keeps whichever value `combinePerfChunks_` collapsed first.
- **Shift:** Video-ness is now derived, once, from the MCO Inventory Group name — `isVideoFmt(c)`,
  VAST ⇒ Video — and the chart, the table's Video quick-filter and the per-creative Video tag all read
  it, so the Video section and the format table can no longer disagree. `check_single_source.py`
  fails on any `c.is_video` read in `Dashboard.html`. More generally: a boolean column on the fact
  table is not automatically a better source than a name we already group on — check it against the
  dimension before trusting it.
- **Watch:** Two things the smoke test now covers by accident of having been wrong. (1) The demo
  fixtures carry no `is_video` field, so the old rule filed *every* demo creative under Non-video and
  the chart still looked plausible — degenerate aggregation reads as real data, so pin expected
  bucket counts, not just "did not throw". (2) `isVideoFmt` reads the group name from `MCO_GROUP_MAP`
  (via `getConfig()`); before config arrives `invToDN` returns the raw `inventory_format`, which
  still says "vast" for every VAST format *except* `native-video` — that one base is matched
  explicitly, and any new format whose raw name omits "vast" needs the same treatment.
- **Watch:** `result.typeBreakdown` (Code.js `fetchTypeBreakdown`, one of the 13 batched queries) is
  no longer rendered anywhere — the charts and the AI payload both compute from `creativePerf` via
  `aggregateBreakdown()`/`bdForAI()`. It is also `is_video_creative`-keyed, i.e. built on the flag we
  just stopped trusting. Candidate for deletion, which would drop a query from the batch.
