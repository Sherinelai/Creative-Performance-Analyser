## 2026-08-17 — 8f929c5f-1f0e-4395-9e7c-b3abc8459d64

- **Finding:** `analytics.daily_attr_event_d7.is_video_creative` does not describe the format a
  creative serves in, and cannot classify Video vs Non-video. Over one baked day: ~3,900 creatives
  carrying $200K+ of spend sat on VAST `inventory_format`s while the flag said `'false'`; a few
  hundred non-VAST creatives said `'true'`; and a third value, `'UNMATCHED'`, exists and fell into
  Non-video under the old `String(c.is_video)==='true'` ternary. Per campaign it *decides* the chart
  rather than nudging it — 82323 has 40 of 80 creatives on VAST formats and the flag marks **0** as
  video; 38469 has 10 VAST creatives against a flag count of 1. It is unstable *within* a creative
  too: 38 of 91,634 carried two values in one day, and with `is_video` in the 17-column perf
  `GROUP BY` the surviving row keeps whichever value `combinePerfChunks_` collapsed first.
- **Shift:** video-ness is derived once, from the MCO Inventory Group name — `isVideoFmt(c)`, VAST ⇒
  Video — and the chart, the table's Video quick-filter and the per-creative Video tag all read it, so
  the Video section and the format table can no longer disagree. `check_single_source.py` fails on any
  `c.is_video` read in `Dashboard.html`. The general lesson: **a boolean column on the fact table is
  not a better source than a name we already group on.** Check it against the dimension before
  trusting it — one `GROUP BY inventory_format, is_video_creative` was enough to disqualify this one,
  and the first campaign I sampled (77022) agreed perfectly, so a single spot-check would have
  confirmed the wrong thing.
- **Watch:** degenerate aggregation reads as real data. The demo fixtures carry no `is_video` field at
  all, so the old rule filed *every* demo creative under Non-video and drew a plausible chart while
  being entirely wrong — `render_smoke_test.js` now pins expected bucket counts (cpr 11/7, cpa 9/6),
  because "did not throw" could never have caught it.
- **Watch:** `isVideoFmt` reads the group name from `MCO_GROUP_MAP` (via `getConfig()`); before config
  arrives `invToDN` returns the raw `inventory_format`, which still says "vast" for every VAST format
  *except* `native-video` — matched explicitly. Any new format whose raw name omits "vast" needs the
  same treatment.
- **Watch:** `result.typeBreakdown` (`fetchTypeBreakdown`, one of the 13 batched queries) is no longer
  rendered anywhere — the charts and the AI payload both compute from `creativePerf` via
  `aggregateBreakdown()` / `bdForAI()` — and it is keyed on the flag just retired. Candidate for
  deletion, which would drop a query from the batch.
