## 2026-07-27 — c45927d9-4e32-4c69-b0ed-9d6bfbec102a

- **Shift (the through-line):** every real bug this session was **the same fact derived twice**, and
  each only surfaced when two consumers disagreed on screen. MCO rules in 4 places, the format
  mapping in 4, metric direction in 4, the performance classes in 2, the primary metric in 3, "which
  creatives are paused" in 2, the Claude call in 2. Fix shape that worked: the fact as data in one
  object (`MCO_RULES`, `METRICS`), prose compiled from one `.md` (`tools/sync_skill.py`), one
  classifier, one resolver, `getConfig()` as the single channel to the client, plus
  `tools/check_single_source.py` so it stays true. **Compute once and stamp it on the row; never
  implement the same rule on both sides.**
- **Finding (the sharpest instance):** a **count in a badge must come from the same rows as the count
  it sits beside.** The "N paused" badge was the row count of the pauseLog query, which carries
  filters the KPI tile doesn't — `HAVING SUM(cstudio_analytics_daily_v1.revenue_micros)/1e6 > 1` (a
  *different revenue table* from everything else in the dashboard, plus an arbitrary $1 floor),
  `inventory_format IS NOT NULL`, and a different window. Campaign 41535: tile **36**, badge **7**; of
  the 29 missing, 24 died on the $1 floor (several showed $0.006 of cstudio revenue while having >$1
  in `daily_attr_event_d7`) and 5 had no cstudio rows at all — all 29 genuinely paused. statusLog now
  comes from `creativePerf` and the pauseLog query is **enrichment only** (when, by whom). Generalise:
  an enrichment query must never decide membership.
- **Finding (debugging technique):** when a *visual* breaks, **diff the render path against a
  known-good deployed version before reading the code**. The donut looked wrong; diffing
  `renderSpendInner` / `seriesFromPerf` / `getLegendLabels` / `getLabelColor` / `resizeDonut` and
  friends against v130 showed the geometry was byte-identical, which pointed straight at the *data
  shape* I had introduced — metric-less queued rows entering the spend series with value 0, adding 0%
  legend rows and taking colour slots so every other format's colour shifted. `clasp pull
  --versionNumber N` makes that diff possible.
- **Finding:** *a state meaning "not serving" is invisible to any activity-driven query*, and it
  showed up twice. (a) `queuing` (`current_status='excluded'`) has no rows in
  `analytics.daily_attr_event_d7`, and both the perf query and the misleadingly-named *inventory*
  query are driven by that table — 41535 displayed 3 of 16. Fixed with metric-less rows
  (`is_metricless`), which then had to be excluded from spend visuals. (b) **Detaching a creative from
  a campaign does not pause it** — all three detached creatives on 64417 are still state `'enabled'`,
  so they count as Active and appear nowhere as a change. Both now surface in the UI.
- **Finding (SQL performance, twice):** push the filter **inside** the CTE. The supplied unassigned-
  creatives query filtered only in the outer WHERE, leaving the CTE to aggregate the whole
  `elephant_changes` audit table — 120s timeout through the SQL Runner; filtering inside the CTE on
  the raw JSON string (`json_extract_scalar(...) = '<id>'`, no CAST) plus a `logged_at` bound gives
  ~18s. Counter-example worth remembering: the same instinct was **wrong** for the perf query's
  unscoped CTEs — aggregating 1,581,908 rows costs 6.3s vs 5.0s scoped. Measure before optimising.
- **Finding (load time, measured):** per-query timings on 77022 — perf **40.3s**, dailyFmt **28.4s**,
  dailyCr **26.3s**, rest 4–8s. The second `runSQLParallel` batch was a **pure barrier** (every query
  in it needed only campaignId + lookbackDays), costing ~28s of a ~68s load; merged into one batch.
  There is a **~4–5s floor per query** (SQL Runner round trip + Trino planning) and slug creation is
  still sequential. Also cut AI cost: diagnoses are fetched **on click** now — fixing the badge would
  otherwise have taken 41535 from 7 prefetched Claude calls to 36.
- **Finding:** *test a campaign of a different shape or you never run the branch.* 41535/77022 were
  ROAS; the CPA branch held a bug. On 78934 `campaign_type` is `'brand'`, so `detectTypeFromName`
  guesses from the campaign NAME and defaults to `ua_cpr` (ROAS) while `goal_2='rpa'` — my
  campType-derived label rendered "7D ROAS" over RPA numbers. `resolvePrimaryMetric_` now decides once:
  optimization_state and goals first, campaign type only as fallback.
- **Shift (hard-won):** *`node --check` is not a test.* v132 shipped `R._metricLabel(...)` from a blind
  `str.replace` that matched **mid-identifier** (`isCpa?'RPA':'ROAS')` inside `R._isCpa?…`). Valid
  syntax; at runtime a mid-render throw leaves the rest of the DOM unwritten, so the page died after
  the campaign summary. `node tools/render_smoke_test.js` runs the real chain under a Proxy DOM stub
  with `CFG` empty (worst case) — reproduce the failure on the broken file before trusting the fix.
  Never blind-replace in a minified line. Keep fixtures that exercise new data shapes (a metric-less
  row lives in the demo data for exactly this reason).
- **Shift:** on a production regression, **roll back first, diagnose second.** `clasp redeploy
  <deploymentId> [-V n]` updates the existing deployment and **keeps the /exec URL**;
  `create-deployment` mints a new URL and leaves production on the old code. Production is
  version-pinned, so `clasp push -f` alone is safe — the separate `@HEAD` deployment is where the user
  verifies before promoting.
- **Finding:** *creative state is READ, not derived* — three mutually exclusive states from the queue
  PDT; the 25K/7-day rule only says when the platform flips `is_currently_optimizing`. Related smell:
  **collapsing a mutually-exclusive enum into "one value + a boolean"** (`lifecycle_state='exploring'`
  + `is_queuing`) — the double-count is automatic once two consumers read different halves.
- **Finding:** the code twice assumed 2 states where the source has more — `campaigns.state`
  (enabled/paused/hidden/deleted) and `creatives.state` (enabled/paused/deleted, which is why
  Active+Paused ≠ Total). **Query the state distribution before reasoning about a state filter.** Also:
  Query E can return a NULL `creative_id` row; `variance` (the gate on every performance class) needs
  a confidence interval — 21 of 79 on 41535, ~half on 78934 — so ⚠ Poor only ever screens a fraction,
  which the recommendation now states.
- **Finding:** Trino rejects `ORDER BY` expressions absent from a `SELECT DISTINCT` select list.
  Dated Looker PDTs need a *verified* resolver (`resolvePDT_` proves via `SHOW COLUMNS` that the
  columns exist — for the queue PDT those columns *are* the state definition). `runHealthCheck()`
  (14 checks) is the pre-deploy gate and how the user confirms Script Properties.
- **Shift:** model-id bumps are not string swaps. On `claude-sonnet-5` adaptive thinking is **on when
  `thinking` is omitted** and `max_tokens` caps thinking + response *together* — the inherited
  `max_tokens: 1024` would have truncated the JSON into a generic "unavailable". Check the thinking
  default and the token budget together, plus params that now 400 (`temperature` on Opus 4.7+).
