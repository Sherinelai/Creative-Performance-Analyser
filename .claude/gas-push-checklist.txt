⚠️ Pre-push checklist for appscript/ (Code.js / Dashboard.html changed in the last commit).

DEPLOY
  • `clasp push -f` from appscript/ — without -f a non-interactive shell prints "Skipping push." and
    uploads NOTHING. If the output does not list the changed files, the push FAILED.
  • push only updates the HEAD version. The /exec web app keeps serving the OLD code until you
    redeploy (`clasp create-deployment`, or Deploy → Manage deployments in the editor).
  • BEFORE redeploying: run `runHealthCheck()` from the Apps Script editor. It verifies the Script
    Properties (incl. LOOKER_CLIENT_ID), Looker auth, Trino, both dated PDTs and their required
    columns, that the three creative-state predicates return data, and that the AI prompt carries
    all three data blocks. It keeps going after a failure, so one run lists everything wrong.

DASHBOARD.HTML
  • Served with createHtmlOutputFromFile (NOT createTemplate) — there are no <?= ?> scriptlets and no
    GAS-side escaping of the file. If you ever switch to a template, every ${...} and \' in it starts
    being processed by GAS first and will silently break the browser JS.
  • It is one file: inline CSS + JS + markup, ~3.1k lines. Client JS runs in the browser sandbox —
    `google.script.run` is async with no return value; use .withSuccessHandler/.withFailureHandler.

CODE.JS
  • V8 runtime, but the file is written in ES5 style (var, function(){}). Match it.
  • Every new query must go through runSQL / runSQLParallel — one statement per call.
  • New tables/columns: verify with run_trino (creative-mcp) BEFORE pushing. The
    looker.*cstudio__creative_format* PDT name is dated — use getPDT(), never a literal.
  • Respect DATA_BAKE_DAYS = 7 (attribution not settled) or the metric reads low.

RUN BOTH CHECKS BEFORE PUSHING (they are guards, not suggestions)
  • node tools/render_smoke_test.js          ← executes the whole render chain on demo data.
    `node --check` only proves the file PARSES. A TypeError mid-render (a bad identifier, a
    call on undefined) leaves the page rendered up to the throw point and blank after it —
    exactly how v132 shipped with only the campaign summary visible. This catches that.
  • python3 tools/check_single_source.py     ← must pass; also runs sync_skill.py --check
  • edited skills/mco-creative-explainer/SKILL.md? run `python3 tools/sync_skill.py` first,
    or the prompt the model receives is the OLD prose.
  • MCO thresholds live ONLY in MCO_RULES, metric meanings ONLY in METRICS, the format mapping
    ONLY in MCO_GROUP_MAP_GS — all reach Dashboard.html through getConfig(). Never add a literal.

SECRETS
  • No API keys or client secrets in source — Script Properties only (CLAUDE_API_KEY,
    LOOKER_CLIENT_SECRET, SKILL_FILE_ID, KB_FILE_ID).
